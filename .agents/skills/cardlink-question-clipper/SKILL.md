# CardLink 摘题制卡

## 1. 确定材料与结构

沿用用户已指定的材料、页范围、目标学习集和结构。采用以下默认方案，只有缺失信息会影响配对、写入目标或授权时才提问。

- **题目和答案在同一份 PDF**：答案是对应题目卡的直接子卡。题目卡使用同一种已选定的题目色，并在 CardLink 的子卡绑定中启用该颜色。没有可确认的答案就只做题目卡。
- **题目和答案在两份 PDF**：在同一学习集下分别建立「题目册」和「答案册」两个脑图分支。完整标题匹配，题答两侧用相同的章节层级和标题。双册的题目标题带章节编号，例如「第3章 第1题」，节内或题组间再重号时附上节号或题组编号。答案卡直接复用题目清单里的完整标题。
- **用户只提供文本**：先将其排成可读的 PDF，保留编号、题干、选项、小问、公式和答案的对应关系，再走 PDF 摘录流程。题目和答案集中在一份 PDF 时，按同源结构处理。

## 2. 准备 Bridge 任务包

本参考只供当前摘题、制卡任务使用。通过可用的 Bridge 工具核实当前运行规程和目标学习集，连接参数沿用工具自身配置。调用前以运行时提供的路由和任务包契约为准。下列路由名和行为来自已有的 v0.93 导入记录，设备端版本变更时重新核对。

1. 确认学习集、文档和 PDF 页范围。目录页码仅作线索，章节首尾和跨页题用 PDF 实际页面核实。文本先转 PDF，核对显示后再上传并加入目标学习集。上传、创建学习集和导入均按用户授权范围执行。
2. 读取任务包支持的模式。考试类 PDF 通常用 `POST /bundles/prepare` 传入 `topicid`、`bookmd5`、`segments`，采用 `exam-general` 和 `block`。一个任务包对应一个 `bookmd5`，同一文档可有多个页段。当前版本返回的页数和并发限制优先。按 job 或 bundle ID 查询状态，等到 `prepared` 后读取该包的 `source.json`、`OUTPUT-CONTRACT.md` 和相关 manifest。任务未结束时查询状态，避免重复发起。
3. 核对准备结果的警告、有效锚定模式和截图格式。已有 `exam-general` 契约对题目和答案同时处理的任务要求使用子卡结构。双册模式分别准备题目 PDF 和答案 PDF，用同一份对照清单生成两个结果。提交前核实当前任务包支持各侧拟写入的结构，尤其确认答案侧能独立成册。导入结构与运行契约冲突且没有已知支持路径时，保留待导入产物并说明卡在哪一侧。
4. 规划各批最终落点。能够确认续批接入原分支、且保留先前数据时继续。否则保留已导入的卡，整理好剩余批次，暂停写入。相同 bundle 的再次提交曾表现为整树替换，把它视为替换操作，以当前契约确定范围。恢复快照也可能影响其他卡片，执行前核对影响范围和授权。

## 3. 摘题并核对对应关系

1. 核对 PDF 页序、章节和阅读顺序。用可缺失或误标的 `role` 和 `section` 辅助定位，遇到跨页、跨栏、共享材料或标记缺失时，回到版面核对。原文的整道大题做一张题目卡，含题干、材料、选项、图表和全部小问。引用共享材料的题目均保留该材料。题目卡的摘录范围止于题目内容。
2. 按「章节或题组＋原书题号」维护一份题答对照清单，记下标题、题目和答案的来源页与摘录锚点。两侧章节叫法不同时，先核实章节对应关系。发现编号冲突，先核实原版面再配对。
3. 原书缺答案或对应关系不确定时，题目照常导入，答案留空。分别在交付清单里标明缺答和待确认。已确定归属的答案优先裁出本题范围，内容分散时用多段原文摘录拼齐。确实裁不开就保留整块，允许同一截图显示相邻答案。

## 4. 生成 result.md

标题只写入卡片标题栏。题目卡及答案卡的内容只保留原文摘录截图，Markdown 标题下只写摘录锚点和必要的样式元数据。按当前任务包的导入契约生成 `result.md`，具体层级和模板见 下方示例。

- 使用块锚点时，只引用当前 `source.json` 中的真实 ID。跨页和跨栏题按阅读顺序覆盖所需块。整块含多个答案时，先用当前导入工具支持的范围摘录裁切，内容分散时保留多段摘录；裁不开时引用整块。没有支持的裁切方式时也使用该整块方案。
- 题目或答案内容只用能生成截图的锚定方式。已有契约中的 `[excerpt: …]` 属于文本引用，默认用 `[block: …]` 生成图片摘录。子卡模式按运行时色板选题目颜色，按契约写样式元数据。

### 双册标题

- 题目标题带原书章节号和题号。章内重复编号时，加入足以区分的节号或题组编号。标题须在整个答案绑定范围内按归一化结果唯一，包括之前导入的批次。
- 从题答对照清单生成标题，答案侧直接复用题目侧标题。题目册、答案册分支可以分别命名，两侧对应章节卡用同名。
- 标题匹配按 NFKC、去空白、去 `？?。．.!！：:`、小写的结果比较。不用仅改变空格或句点来区分两题。例如 `3.12` 和 `31.2` 都归一化为 `312`。
- 已提交的 CardLink 2.4.7 源码要求直接父级归一化后同名。审查时标为 2.4.8-b68 的工作树会优先选择同父候选，没有同父候选时回退到同标题候选。保持两侧章节同名且标题在绑定范围内唯一，可兼顾这两种行为。章节名归一化可能去除「第X章」等前缀，所以使用完整章节名，并把必要的编号写进题目标题。

维护时核对目标版本的 `src/answer-lookup.ts`、`src/binding.ts`、`src/domain.ts`、`src/ordered-pairing-domain.ts` 与 `tests/answer-parent-filter.test.ts`。设备上安装的版本应以用户界面为准。

### 导入模板

下文块 ID 和色号均为示例，使用时替换为当前任务包的有效块 ID 和目标学习集实际色号。标题层级描述父子关系，标题后可有机器元数据和截图锚点。保持正文为空。不使用 `[[标题]]`，该语法会把卡片合并。

#### 同源子卡

```markdown
# 高数题目
## 第三章 函数极限
### 第1题
[style: colorIndex=11]
[block: b_12_0, b_12_1]
#### 第1题答案
[block: b_18_4]
```

#### 双册分支

两个任务包分别生成各自的结果，截图锚点只引用该包中的块。以下是各自的逻辑分支。最终导入及续接按上面的任务包规则核实。

题目侧：

```markdown
# 题目册
## 第三章 函数极限
### 第3章 第1题
[block: b_12_0, b_12_1]
```

答案侧：

```markdown
# 答案册
## 第三章 函数极限
### 第3章 第1题
[block: b_51_5, b_51_6]
```

## 5. 提交并核对落卡

1. 对照清单核对题答数量、标题归一化后的唯一性、题答关系、截图范围和目标分支。用户明确授权后按原范围写入，范围或目标发生变化时再确认。调用 `POST /bundles/{bundleId}/submit`，提交 `{"resultMarkdown":"<result.md 全文>"}`。命令行发送请求时，使用 UTF-8 文件传输 JSON。等待最终结果。遇到超时或 `SUBMIT_IN_FLIGHT` 先查询状态，再判断是否需要重提。
2. 对照预计卡片数和实际标题，处理回执的警告。用导入根的树形读回核对章节或子卡关系，用批量笔记读回核对摘录和题目颜色；历史 v0.93 的批量读回参数为 `noteIds`。已有回执里的 `excerptsTotal` 只统计文本引用，块截图在读回的 `parts` 中核对 `excerpt_image`。回执里的 `childCount` 也可能只计内容卡。
3. 记录各批的目标、处理结果和返回的快照 ID（若有）。保留续批或故障排查所需的结果，完成后按当前契约清理已结任务包。交付时说明已导入的题答数量、缺答、待确认、未写入批次和 CardLink 的绑定步骤。

已有导入记录覆盖 Markdown 父子层级、色号和块截图落卡。跨包接入同一分支、裁切能力及 CardLink 实际显示应按当前工具契约或设备反馈判断。导入后的结构检查属于交付核对，批量任务可按已授权范围开展。

## 6. 交付用户自行配置 CardLink

MN Bridge 用于摘题、导入和读回卡片。交付时把对应操作步骤告诉用户，由用户在 MarginNote 的 CardLink 界面完成。

| 材料 | 默认组织 | 用户在 CardLink 中的操作 |
| --- | --- | --- |
| 同一份 PDF | 章节下放题目卡，答案放在对应题目卡正下一层 | 绑定子卡片，在对应绑定的「筛选题目」里启用题目卡使用的颜色 |
| 两份 PDF | 同一学习集下建「题目册」「答案册」两个脑图分支，两侧章节结构一致 | 开启「多题目脑图独立绑定」，从题目分支绑定答案分支，选择「完整标题匹配」 |

双册模式下，追加或修改答案卡后，提醒用户在对应的答案脑图绑定中点「刷新答案索引」。子卡模式通过绑定、题目颜色和实际父子关系找到答案，答案子卡标题采用「题目标题＋答案」作为显示约定。把材料和选项做成题目摘录的一部分，避免额外内容卡处在答案子卡的位置。
